1. Introduction

YATRA is a premium, fully responsive front-end web application designed as an editorial India travel magazine. The primary objective of this project is to demonstrate advanced front-end web development skills without relying on a backend server or external database. By leveraging Modern JavaScript (ES6), HTML5, and CSS3, the application provides a dynamic, Single Page Application (SPA) experience.

Users can browse through 40+ curated travel stories across six distinct Indian states (Delhi, Rajasthan, Gujarat, Goa, Kerala, and Assam). The platform features an interactive article discovery engine, persistent local bookmarking, and a unique "Write a Story" module that allows users to publish their own blogs locally.

2. Technologies Used

  • HTML5: Used for semantic structuring of the web pages (using tags like <nav>, <main>, <article>, and <aside>).
  • CSS3 (Custom Variables & Grid/Flexbox): Used for creating a responsive, editorial magazine layout. CSS Variables (--primary, --terracotta) ensure a consistent color palette across all pages.
  • Vanilla JavaScript (ES6): Used for DOM manipulation, event handling, data filtering, and routing. No external frameworks (like React or Angular) or libraries (like jQuery) were used, strictly adhering to the syllabus constraints.
  • Web Storage API (localStorage): Used as a client-side database to persistently store user sessions, saved bookmarks, and user-generated articles.
  • FileReader API: Used to convert user-uploaded images into Base64 encoded strings for local storage.

3. Project Architecture & Design Pattern

YATRA follows a Client-Side Rendering (CSR) approach. Since there is no backend (like Node.js/Python) or database (like MySQL/MongoDB), the data layer is handled entirely within the browser.

All 43 pre-written travel articles are stored in a massive JSON object inside js/articles.js. When a user clicks on a story, they are taken to blog.html?id=story-name. The JavaScript on that page reads the id parameter from the URL, looks up the data in the JSON object, and dynamically injects the HTML into the page. This eliminates the need to create 43 separate HTML files, proving a modular and scalable architecture.

4. File Structure & Directory Layout

The workspace is organized into a logical structure separating assets, logic, and views:

  • index.html - The Landing/Login page featuring a full-screen background and glassmorphism login modal.

5. Detailed Module Description

A. Authentication Module (Demo Mode)

Located on index.html. Because this is a frontend-only project, true authentication cannot be implemented. Instead, it uses a "Demo Mode". When a user enters an email or clicks "Continue as Guest", JavaScript intercepts the form submission, prevents the default page reload, and writes a session token (e.g., yatra_user: guest) into localStorage before redirecting to the homepage.

B. Article Discovery Engine

Located on home.html. It features a real-time search bar and category buttons. The logic works by creating an array of all available articles. When the user types in the search box, the Array.prototype.filter() method checks if the search string exists in the article's title, state, or excerpt. The filtered array is then mapped into HTML template strings and injected into the DOM. This happens instantly on the client side without network latency.

C. User Publishing Module (Write a Story)

Located on write.html. Users can input a title, category, author name, and body text. A critical technical achievement here is image handling. The <input type="file"> triggers a FileReader object which converts the uploaded image into a Base64 Data URL. The entire form data is structured into a JSON object and pushed into an array called yatra_user_articles inside localStorage.

6. Data Flow & State Management

To ensure user-generated articles appear alongside hardcoded articles, the system uses a clever merge strategy upon initialization. Inside js/articles.js, the script executes the following logic:


try {
  // Fetch hardcoded articles
  const defaultArticles = articlesData; 
  // Fetch user articles from LocalStorage
  const userArticles = JSON.parse(localStorage.getItem('yatra_user_articles')) || {};
  // Merge both into the global window object
  window.articlesData = { ...defaultArticles, ...userArticles };
} catch(e) {
  console.error("Data load failed", e);
}

By attaching the merged object to the global window object, every subsequent script on any HTML page has immediate, synchronous access to the complete database.

7. Comprehensive Viva Q&A Guide

1. How do you pass data between different HTML pages without a backend?
We use two primary methods. First, we use URL Query Parameters (like blog.html?id=delhi). The receiving page parses this URL using new URLSearchParams(window.location.search) to know what data to render. Second, we use the Browser's localStorage API to save persistent data (like Bookmarks) across sessions.
2. If there is no database, where do the articles come from?
The pre-written articles are stored as a massive JavaScript Object (JSON) in js/articles.js. This script is loaded on every page, attaching the data to the global window.articlesData object so the DOM can read it instantly without an HTTP fetch request.
3. How do you upload and display images in the "Write a Story" feature without a server?
We utilize the HTML5 FileReader API. It reads the user's uploaded file locally and converts it into a "Base64 Data URL" (a long string of text representing the image). We save this string inside localStorage and use it directly inside the src attribute of an image tag.
4. Why did you use CSS Grid vs Flexbox?
Both are utilized for their specific strengths. Flexbox is used for 1-dimensional layouts (like aligning items in the navigation bar or side-by-side buttons). CSS Grid is used for 2-dimensional layouts (like the Homepage Article Feed or the Split-screen layout) where we need strict rows and columns that wrap cleanly.
5. What is an IIFE and did you use it?
An IIFE (Immediately Invoked Function Expression) is a JavaScript function that runs as soon as it is defined. We used it in blog.html (() => { ... })(); to encapsulate the article rendering logic so our variables don't pollute the global scope.
6. How did you handle errors if an article ID doesn't exist?
In blog.html, after reading the ID from the URL, we check if window.articlesData[id] exists. If it returns undefined, we intercept the rendering process and update the DOM's innerHTML to display a friendly "404 - Story Not Found" message instead of throwing a console error.
7. How does the Search functionality work technically?
We attach an input event listener to the search bar. Whenever the user types, it reads the .value, converts it to lowercase, and runs the .filter() array method against the articles array. It checks if the title or excerpt .includes() the search string, and instantly re-renders the DOM with the matching results.

8. Limitations & Future Scope

  • Limitation: localStorage has a strict size limit (usually ~5MB per domain). If a user uploads too many high-resolution Base64 images, the storage will crash.
  • Limitation: Because there is no backend, bookmarks and written stories are tied to the specific browser and device. They cannot be accessed from a different computer.
  • Future Scope: In the next semester, this project can be upgraded by connecting it to a Node.js/Express backend and a MongoDB database. This would allow for real user authentication (JWT), infinite image storage (AWS S3), and global sharing of user-written blogs.

9. Conclusion

The YATRA project successfully demonstrates that highly interactive, data-driven web applications can be constructed using core web technologies (HTML, CSS, JS). By implementing client-side routing, local state management, and real-time DOM manipulation, the project fulfills all academic requirements while delivering a production-grade user interface.
