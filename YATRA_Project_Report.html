1. Introduction & Architecture Overview

YATRA is a completely static, front-end only travel magazine. Because academic guidelines prohibited the use of a Node.js/Python backend server or a SQL/MongoDB database, this project heavily relies on advanced Vanilla JavaScript (ES6) and the HTML5 Web Storage API.

The "No-Backend" Secret
All user actions—logging in, saving bookmarks, writing new blogs, and uploading images—are processed instantly in the browser and stored locally on the user's hard drive using localStorage. The website merges this local data with a hardcoded JSON file upon page load, creating the illusion of a fully functional, globally connected database.

2. Module 1: The Login & Authentication System (index.html)

The entry point of the website. It features a full-screen, high-resolution static background of a Rajasthan fort, overlaid with a frosted-glass ("glassmorphism") modal box.

Every Feature Explained:

  • Email & Password Fields: Standard HTML5 required inputs.
  • Password Visibility Toggle (👁): A JavaScript event listener attached to the eye icon. When clicked, it toggles the password input's type attribute from "password" to "text" (and vice versa), allowing the user to reveal what they typed.
  • Log In Button: When clicked, JavaScript intercepts the form submission (using e.preventDefault()). Instead of sending the password to a server, it takes the email, saves it into localStorage.setItem('yatra_user', email), and redirects the browser to home.html.
  • Social Login & Guest Buttons: These are demo buttons. Clicking them triggers an identical logic flow to the main Login button, but they hardcode the username as "google_user", "microsoft_user", or "guest_user" before redirecting.

3. Module 2: The Main Dashboard (home.html)

The homepage acts as the central hub. It contains a full-viewport hero image, a Navigation Bar, a Destination Grid, and an interactive Article Discovery Archive.

Every Feature Explained:

  • Navigation Bar (Write & Saved): Fixed at the top of the screen. As the user scrolls down, a JavaScript scroll listener detects the window position and changes the navbar background from transparent to solid white to ensure the links remain readable over the text.
  • Destinations Grid (The 6 Cards): Six image cards representing the 6 states (Delhi, Goa, Rajasthan, etc.). These are direct hyperlink tags (<a>) that transport the user to the respective state HTML page.
  • The Archive Search Bar: A dynamic text input. An 'input' event listener watches every keystroke. It reads the text, converts it to lowercase, and uses the Array.filter() method to search through every article's title, excerpt, and state in the database, instantly re-rendering the cards on the screen without reloading the page.
  • Category Filters (Heritage, Nature, etc.): A row of buttons. Clicking a button changes a JavaScript variable (currentCat) and triggers the same filtering function mentioned above, showing only articles matching that category.
  • Sorting Dropdown: Contains "Latest First" and "A to Z". Choosing "A to Z" runs the JavaScript .sort((a,b) => a.title.localeCompare(b.title)) method on the array before rendering the cards.

4. Module 3: Dynamic Article Rendering (blog.html)

Instead of creating 50 different HTML files for 50 different stories, there is only one file: blog.html. This is the core of the Single Page Application (SPA) design pattern.

Every Feature Explained:

  • URL Query Parsing: When a user clicks a story on the homepage, the link looks like this: blog.html?id=goa-beaches. The JavaScript on blog.html uses new URLSearchParams(window.location.search) to extract the word "goa-beaches".
  • Dynamic Injection: The script looks up "goa-beaches" in the global window.articlesData database. It extracts the title, image URL, and text paragraphs, and uses innerHTML to inject them into the blank HTML template.
  • Not Found Error Handling: If a user types a fake ID into the URL bar, the script detects that the data is undefined and immediately replaces the screen with a graceful "Story not found" message, avoiding a crash.
  • "Save to Yatra" Button: Located in the sidebar. When clicked, it grabs the current article ID and pushes it into an array called yatra_saved_posts stored in the browser's localStorage. The button immediately turns orange and changes text to "Saved!"

5. Module 4: State Hubs & Tourist Sentiment (delhi.html, etc.)

Each of the 6 states has its own dedicated page. These pages feature a horizontal feed of stories specifically about that state.

Every Feature Explained:

  • Auto-Filtering Feed: Similar to the homepage, but the JavaScript is hardcoded to only filter and display articles where article.state === "Delhi".
  • Tourist Sentiment Dashboard: A complex data visualization module. It fetches mock data from data/sentiment.json and uses the Chart.js library to draw a responsive, horizontal bar chart showing the percentage of Positive, Neutral, and Negative tourist reviews for that state.
  • Write a Review Form: A standard HTML form at the bottom of the page. Because there is no backend server to process form emails, submitting this form simply triggers a JavaScript alert() thanking the user, and clears the input fields.

6. Module 5: User Publishing Engine (write.html)

The most technically advanced feature of the project. It allows visitors to author their own travel blogs and publish them directly to the website locally.

Every Feature Explained:

  • Text Inputs & Dropdowns: Standard fields for Title, Author, Excerpt, State, and Category.
  • Image Upload & FileReader API: When a user clicks the dashed box and selects a JPEG/PNG from their computer, a JavaScript FileReader object reads the binary file and converts it into a "Base64 Data URL". This translates the image into a massive string of plain text characters, which allows it to be saved directly into local browser memory without needing an Amazon S3 server.
  • Publish Button: When clicked, the script bundles all the text inputs and the Base64 image string into a new JSON object. It assigns it a unique ID (e.g., user-12345-my-trip), saves it to localStorage, and redirects the user to their newly created blog.html?id=user-... page.

7. Module 6: Persistent Bookmarking (saved.html)

The user's personal dashboard for stories they want to read later.

Every Feature Explained:

  • Grid Rendering: The script opens localStorage, retrieves the array of saved IDs, loops through them, looks up their data in the master database, and renders them as cards.
  • Empty State: If the array is empty, it displays a dashed box saying "You haven't saved any stories yet," prompting the user to explore the site.
  • Remove / Unsave: Since the user has complete control over their local data, clicking the heart/save icon on an already saved article will filter that ID out of the localStorage array, permanently removing it from the Saved page.

8. Core Data Management & File Structure

To make the user-published blogs appear alongside the professional YATRA blogs, the system relies on a seamless data-merging pipeline upon every page load.

The Data Merge Pipeline (js/articles.js)
At the bottom of the database file, the following JavaScript executes instantly on every page load:

const userArticles = JSON.parse(localStorage.getItem('yatra_user_articles')) || {};
window.articlesData = { ...articlesData, ...userArticles };

This combines the 43 hardcoded JSON articles with any custom articles the user created in write.html. Because this combined object is assigned to the global window scope, the Search Bar, the State Pages, and the Saved Page will automatically include the user's custom blogs seamlessly.
